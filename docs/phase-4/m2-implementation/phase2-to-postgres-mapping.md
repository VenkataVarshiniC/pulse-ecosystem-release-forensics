# Frozen Phase 2 to PostgreSQL mapping

M2.2 indexes only pytest 8.0.0 (two members) and urllib3 2.0.0 (six). Deterministic UUIDv5 values use a PULSE M2.2 namespace plus immutable source keys. Rebuilding from the same manifest produces the same release, repository, case, membership, run, task, capture, observation, pair, candidate, review, assessment and finding identities. Cohort membership uses its `(case_version_id, repository_id)` key. A capture UUID uses logical root and relative path, **not** content hash, so separate captures of identical bytes remain separate. The load audit uses a stable case idempotency key and manifest fingerprint.

| Frozen source | Typed destination and governing rule |
| --- | --- |
| Case YAML and report | `core.dependency_release`, `investigation_case` FROZEN, `repository`, `cohort_membership`; release time/window come from the YAML and are cross-checked against the report. |
| Collector run manifest and 54 journals | Two release `collection_run` rows, 54 `collection_task` rows and 54 `task_attempt` rows. Each journal supports exactly one initial attempt; retry count is zero. Required, optional and `not_found` remain distinct. Three upstream tasks per case legitimately have no cohort repository. |
| Historical run manifests | Two additional `collection_run` rows with `historical_reconstruction` kind. Their raw captures retain source task/attempt keys, but no fabricated planned task or attempt rows are created. |
| Raw captures | 72 `evidence_artifact` rows with source locator, digest, ref where available, retrieval/event time, capture method `collector`, logical raw pointer and task or history-run link. `repository_alias` and release source-artifact links point to the underlying verified captures. Only observed providers/types enter `source_registry`. |
| Frozen historical reconstruction | 8 `PATH_STATE` and 3 `HISTORICAL_DECLARATION` observations. The latter are parsed target declarations, not resolved versions or inferred adoption. Sixteen pair decisions retain `PAIRED`, `AFTER_ONLY` or `UNRESOLVED`; after-only is not paired. No current-declaration row is invented from unsupported parser output. |
| Baseline and independent review ledger | Two separate urllib3 `candidate` identities from one PR artifact, both `EMITTED` with `COPIED_UPSTREAM` source origin. Two `analyst_review` rows reject them. Event time on the PR is not candidate emission time, so `emitted_at` is NULL. No pytest candidate or review is fabricated. |
| Report stage sufficiency/findings | Forty `sufficiency_assessment` and forty `lifecycle_finding` rows at case/member/category grain. Phase 2's `true` sufficiency maps to `SUFFICIENT`; `false` maps to `LEGACY_UNCLASSIFIED`, because the source does not distinguish insufficient, unavailable and conflicting. The 38 UNKNOWN findings stay UNKNOWN; two source-supported bounded NO findings stay `NO_QUALIFYING_EVIDENCE_FOUND`. No source assessment/finding timestamp is invented. |
| Replay audit | Four case-scoped `replay_attempt` rows, two matched attempts per case, with frozen report digest and audit-source digest. |
| Input/load identity | Two successful `load_audit` rows and two `analysis_snapshot` rows in `DRAFT` state, with typed links to each case's runs, captures, candidates, reviews, assessments and findings. No snapshot is published. |

The frozen reports contain no accepted positive event IDs. Their UNKNOWN findings have no qualifying finding-support edge; adding one would misrepresent source evidence. Snapshot edges preserve the report-derived finding lineage, and raw capture, candidate/review and historical observation edges preserve the available evidence chain. The `LEGACY_UNCLASSIFIED` status is a deliberate V002 vocabulary extension; it is not a claim of `INSUFFICIENT` or `SOURCE_UNAVAILABLE`. V003 permits absent interpretation timestamps, and V004 preserves raw historical task/attempt source keys without implying a task journal exists.

These rows are evidence categories, not a chronological lifecycle. The loader never reconstructs or asserts a causal event chain. The database remains a governed representation of frozen source files, not a new collection or detection run.

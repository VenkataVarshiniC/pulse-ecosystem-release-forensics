# Investigation/evidence pathway specification

This is a diagnostic **investigation funnel**, not a user-conversion funnel. It has a compulsory declared-member spine and an optional candidate/review branch. A repository with no candidate can still receive a bounded no-qualifying-evidence finding when stage-specific source/history/review prerequisites are satisfied. Conversely, a candidate does not make a finding. Stage categories may occur in any chronological order and do not imply causality.

| Step | Business meaning; grain | Qualification / numerator | Denominator / transition | Exclusions and UNKNOWN |
| --- | --- | --- | --- | --- |
| F0 Declared | Case's frozen member set; case × repository. | All unique membership keys. | Cohort size; root for all member views. | No removal for failed collection, no dedup across distinct cases. |
| F1 Core collected | Planned required metadata/issues/PRs/commits complete; member. | Members satisfying MET-001. | F0 for coverage; F1/F0 conditional share. | Optional verified 404 does not fail required collection; missing task result fails qualification. |
| F2 Context established | Parsed exact-ref target declaration; member, with paired-pre-release and after-only **separate subcounts**. | Members satisfying MET-002. | F0, and optionally F2∩F1/F1 as conditional context yield. | Current declaration excluded; after-only cannot enter negative release-window eligibility. F2 is not necessarily prerequisite for every positive stage finding. |
| F3 Stage sufficient | Source and context/review prerequisites met for a **specific category**; member × stage. | Members with sufficient assessment (MET-005) for named stage. | All declared members for that named stage; conditional within F1 shown only if applicable. | Missing assessment blocks published rate; UNKNOWN stays visible. Do not sum across stages as unique members. |
| B1 Candidate emitted | Rule fires on preserved artifact; candidate, with distinct member companion. | Candidate IDs; members with ≥1 candidate = MET-008. | Candidate count has no conversion denominator; member coverage uses F0. | No-candidate members stay in F0/F3; no-event inference prohibited. |
| B2 Candidate reviewed | Terminal review exists; candidate. | Terminally reviewed emitted candidate IDs. | B1 candidate IDs, provided complete frozen baseline/ledger. | NEEDS_REVIEW/unreviewed shown separately; missing or duplicate terminal review blocks affected result. |
| B3 Candidate accepted | Qualifying review accepts candidate; candidate. | Accepted emitted candidate IDs. | B2 terminally reviewed candidate IDs (MET-009). | Rejected/unresolved never accepted; 0/0 unavailable. |
| F4 Defensible stage output | YES or bounded NO under assessment; member × stage. | Verified non-UNKNOWN finding for named stage. | Declared members asked that stage. | UNKNOWN is not NO; bounded NO does not assert event absence. A YES may rely on qualified direct observation rather than a candidate if method allows it. |
| F5 Repository outcome available | Required case questions resolved with provenance; member. | Members satisfying MET-006. | F0. | Unspecified required question set makes metric unavailable; this is analytical outcome coverage, not human completion. |

**Transition policy:** do not multiply conditional percentages across F1/F2/F3/B1/B2/B3/F4/F5; branches have different grains and B1 is not a required step for F4. Use a split-path visual with count labels, denominators and an explicit UNKNOWN lane. Report absolute loss from F0 to F1, context gaps F0 minus F2, category-specific F0 minus F3/F4, and review backlog B1 minus B2. These losses are **method gaps**, not user abandonment.

Future SQL should begin from `core.cohort_membership`, left join a single versioned per-member task summary, a context classification, category-specific assessment/finding, and separately aggregate candidate/review IDs before joining member summaries. Join facts only after reducing to the target grain to avoid candidate × artifact × stage fan-out. Publish source-plan and method version with every funnel extract. No SQL or funnel result is executed in this milestone.

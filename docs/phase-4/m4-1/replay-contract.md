# M4.1 offline replay contract

Inputs are exactly the 142 SHA-256-verified entries in `data/manifests/phase2-postgres-load-manifest.json`, including two case definitions, collector captures/attempts, historical query/file captures, two legacy baselines, and one original analyst-review ledger. The current rule manifest is `data/manifests/m4-1-rule-manifest.json`; its own canonical hash and every rule source hash must verify before execution. No external retrieval occurs.

Order: verify input and rule manifests → verify each collection raw root equals the selected frozen snapshots → re-run path pairing and captured file parsing checks → emit text and paired-transition candidates → derive a new rule-release-qualified candidate ID from the normalized full payload → compare to legacy full payload (all fields except candidate ID and review state) → inherit only exact legacy review evidence, retaining original review UUID/decision → regenerate events, coverage, sufficiency and findings through `build_phase2_report`. A nonexact candidate is `REVIEW_REQUIRED`; no report is generated for that case pending review. Replay source origin labels only an explicit quoted upstream span.

The replay output is `data/processed/m4-1/replay.json`. Its candidate IDs and report fingerprints are deterministic. Generated timestamps are absent; source timestamps from frozen captures remain. `scripts/run_m4_1_replay.py --check` computes the entire replay and byte-compares the committed artifact. Re-running must produce no duplicate candidates and identical report fingerprints. The only expected legacy differences are new candidate IDs, explicit current rule provenance, exact-equivalence/review-reuse links, and replay sufficiency vocabulary. Neither original DRAFT snapshot nor any historical candidate/review/finding row is changed.

This replay contract alone does not grant publication. It has no new PostgreSQL snapshot, dbt replay lineage, or all-23 metric result. Those remain required for G6/G7. The M2.5 metric contract and M2.4 mart contract are unchanged; their old result cannot be relabeled as a replay result. Lifecycle categories are not a required chronology or causal chain.

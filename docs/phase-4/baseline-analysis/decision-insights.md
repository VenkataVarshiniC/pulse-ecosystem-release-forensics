# Conditional decision insights from the frozen baseline

These are **consulting-style diagnostic implications**, not final client recommendations or stakeholder-validated priorities. Confidence rates the narrow observation, not business impact.

## 1. Collection is operationally complete but many forensic answers are unresolved

- **Observation:** Core planned-source coverage is 2/2 and 6/6; exact-ref declaration coverage is 1/2 and 1/6; adoption and recovery remain UNKNOWN throughout.
- **Why it matters:** A pipeline-success dashboard alone would overstate answerability.
- **Decision implication:** If the product decision requires observed adoption/recovery, first test source feasibility and sufficiency methods before scaling a database or dashboard.
- **Confidence:** **High** for these frozen reports; **low** for general frequency across repositories.
- **Limitation:** Convenience selection, narrow query plan, missing target-version/downstream sources.
- **Next evidence needed:** Predeclared cases with validated older-anchor/lock/runtime/downstream-source methods and stakeholder-defined question set.

## 2. Candidate count overstates distinct evidence

- **Observation:** Two urllib3 candidate IDs from two rules point to one Dependabot PR artifact and were both rejected.
- **Why it matters:** Candidate-level charts could make one copied-text mechanism look like two independent downstream events.
- **Decision implication:** Any future rule-quality review should show distinct artifact and member counts beside candidate counts.
- **Confidence:** **High** for this artifact; **low** for detector quality beyond it.
- **Limitation:** No independently labeled non-emissions; no recall denominator.
- **Next evidence needed:** Preregistered artifact-level review sample including emitted and non-emitted records, with text-origin coding.

## 3. Versioned grain is an early architecture requirement

- **Observation:** Current report rows are unique by case/member/category, but no finding version or analytical snapshot ID exists; candidate→artifact is many-to-one.
- **Why it matters:** Later joins or repeated loads could duplicate findings and corrupt denominators.
- **Decision implication:** Treat snapshot selection, keys and bridges as a prerequisite for any authorized PostgreSQL/dbt build.
- **Confidence:** **High** for inspected schemas/rows.
- **Limitation:** Positive finding support cardinality cannot be tested with zero YES events.
- **Next evidence needed:** Versioned accepted-evidence example and multi-run design test when a genuine case supplies one.

## 4. A decision dashboard is premature as a value claim

- **Observation:** Bounded diagnostic counts exist, but MET-006 completion and stakeholder-value measures have no approved definitions.
- **Why it matters:** An “investigation completed” executive card could assert a decision standard nobody has agreed to.
- **Decision implication:** Use the current output as a research diagnostic; reconcile the actual user, question set, trust and burden before prioritizing Power BI views.
- **Confidence:** **High** for absent primary evidence; **unknown** for eventual user value.
- **Limitation:** No interviews/Form findings or UAT.
- **Next evidence needed:** Authorized primary-research reconciliation and real decision walkthroughs.

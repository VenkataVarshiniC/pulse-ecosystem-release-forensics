# Source gap matrix and public-source feasibility

This is research, **not** authorization to collect or integrate new data. The possible-source column names an observation to test, not an assertion that it is available for every repository/ref. Public endpoints and data formats were checked against [GitHub contents](https://docs.github.com/en/rest/repos/contents), [commits](https://docs.github.com/en/rest/commits/commits), [releases](https://docs.github.com/en/rest/releases/releases), [check runs](https://docs.github.com/en/rest/checks/runs), [workflow runs](https://docs.github.com/en/rest/actions/workflow-runs), [PyPI JSON](https://docs.pypi.org/api/json/), and [deps.dev v3](https://docs.deps.dev/api/v3/) documentation.

## Source interpretation boundaries

- **GitHub contents/commits:** exact ref and path can make a declaration reproducible, but a 404/current absence is not historical absence. History across file moves and older unchanged states needs an explicit method. Public endpoints do not guarantee complete discoverability under a bounded query.
- **Lockfiles:** a committed resolved version can show a resolution for a named file/ref/environment; it does not by itself prove runtime installation or production use.
- **GitHub checks/Actions:** may expose run/ref/status in public repositories subject to access and retention; an observed pass/fail does not identify the dependency version unless the workflow/artifact records it. No current Phase 2 baseline checks were systematically collected.
- **GitHub releases/tags:** a published downstream release is a release observation, not automatically a successful migration, deployment, or recovery. GitHub's releases endpoint omits ordinary tags lacking a release object; tag evidence needs its own method.
- **PyPI:** upstream package release metadata establishes release identity/time but says nothing about a named downstream repository's installed version or production state.
- **deps.dev:** package/version dependencies and modeled resolutions may inform package-level context; they cannot replace exact repository/ref/runtime evidence for these frozen downstream cases. Its generic resolution semantics need validation for any proposed use.

Reproducibility would require persisting exact query/ref, response timestamp, capture method, payload digest, status/permission outcome and parser version. No new dataset was downloaded for this audit.

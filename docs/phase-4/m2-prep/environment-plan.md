# Future environment, security and deployment plan

**Plan only; nothing is installed or connected.** M2.1 may use local PostgreSQL with pinned server and dbt-postgres versions, Python/uv matching the repository, a repeatable migration tool and isolated development database. Document exact versions and reproducible setup only when implementation is authorized. Power BI Desktop is optional for a later governed semantic build, not required to validate dbt data quality. No cloud provider is selected. A portfolio demo hosting decision requires actual audience, data-access, cost and security constraints.

Conceptual configuration: a committed .env.example would list variable names such as database host/name/user, raw evidence root, source access mode and schema target, with placeholder values only. Real credentials belong in environment or approved secret storage, never repository, raw evidence or reports. Separate future loader write role, dbt transform role and read-only BI role with least-privilege schema grants; avoid broad superuser connections. Restrict raw file access to authorized loader/reviewer. Preserve artifact checksums and an append-only load audit. Backup, retention, deletion, availability and disaster recovery must follow an actual data policy, not an invented SLA.

Default source boundary is declared accessible/public evidence; private repository/CI/SCA access requires permission and terms review before collection. Survey/interview respondent identifiers stay in a separate protected research store and are not joined into forensic marts without a validated purpose. Review identity in core is limited to what audit requires, with display pseudonymization if appropriate. No claim of enterprise compliance is made.

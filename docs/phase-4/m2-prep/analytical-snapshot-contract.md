# Analytical snapshot and publication contract

An analysis_snapshot_id identifies one immutable **publication manifest**, not a mutable current view. Proposed core publication manifest row: UUID PK; case_version_id FK; source_plan_version, rule_version, metric_definition_version, model/dbt_version and loader_version text; ordered chosen run IDs; ordered artifact IDs and SHA-256 digests; chosen candidate baseline, review cycles, assessment IDs, finding IDs, report/output hashes; generated_at timestamptz; manifest_sha256 unique; state DRAFT, VALIDATED, PUBLISHED or REVOKED; supersedes_snapshot_id nullable. Input lists use normalized manifest child rows, not an opaque JSONB blob. The canonical serialization, ordering and hash algorithm are versioned.

Publication sequence: freeze case and source plan; verify referenced raw bytes/digests and case/run/task identity; select exact candidate, review, assessment and finding versions; build canonical manifest; derive fingerprint and stable snapshot ID; run database/dbt and golden checks; publish atomically only after all mandatory checks pass. Equal manifest yields equal identity and analytically equivalent output; changed source, interpretation, model or metric version yields a new snapshot. An old snapshot is never recalculated silently under a new rule. A rejected publication remains auditable and is excluded from BI.

All snapshot-scoped facts carry analysis_snapshot_id, case_version_id and source version context. A dashboard must select one published snapshot per case explicitly; historical comparisons use two explicit IDs. The case's selected member set is compared with every repository mart before publication. A live recollection is a new run, not deterministic replay. generated_at records publication timing and is excluded from deterministic analytical equality.

Current Phase 2 files lack persisted snapshot IDs, observation IDs and finding versions. First authorized load must assign them through a reproducible mapping and retain original file identity; that mapping itself becomes part of the manifest. No snapshot is being created in M2-PREP.

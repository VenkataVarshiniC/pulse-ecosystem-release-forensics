# PostgreSQL type standards

**Proposal only.** Use UUID surrogate PKs for cross-file and cross-run identities; preserve provider natural IDs as text (a provider can exceed signed bigint or change formatting). Bigint is appropriate only for local sequential audit counters if profiling later justifies it. Use text for package/version/specifier/ref/URL: semantic versions and PEP 440 versions are not decimal numbers; normalized package name is a separately stored, versioned parse output. Repository owner/name is a display alias, not stable identity.

Use timestamptz for event, retrieval, attempt, review, load and publication instants. Preserve source timezone/precision in raw evidence; never fill an absent source event with retrieval time. Use date only for a declared date-grain business window, not to truncate a source instant. Booleans express true binary facts such as required_flag, never UNKNOWN. Integer counts have nonnegative CHECK; numeric is for calculated ratios with an explicit denominator and unavailable reason, never a persisted 0 for missing evidence.

Use text plus CHECK/lookup table for controlled statuses and method versions, rather than PostgreSQL enum types that make governed evolution cumbersome. Capture methods are collector, connector_assisted, fixture. Finding states are QUALIFYING_EVIDENCE, NO_QUALIFYING_EVIDENCE_FOUND, UNKNOWN. Sufficiency is SUFFICIENT (method prerequisites met), INSUFFICIENT (available evidence inadequate), SOURCE_UNAVAILABLE (required acquisition failed/not attempted), CONFLICTING (material contradiction). Missing assessment is an integrity defect, not a fifth UNKNOWN sufficiency value. Use text URL/ref fields with scheme/provider and length validation at application load; URL strings are not primary keys. SHA-256 is 64 lowercase hexadecimal characters with CHECK; hash algorithm/version is recorded if extended.

Proposed task terminal values mirror the existing collection outcome vocabulary: succeeded, partial, rate_limited, not_found, unauthorized, failed; a separate pending state is allowed only before terminalization. A verified optional not_found can satisfy an optional probe, while a required not_found is not successful required collection. Proposed run values are complete, incomplete and failed, with running before terminalization. Review decisions are ACCEPT, REJECT and NEEDS_EVIDENCE; legacy NEEDS_REVIEW maps only through an explicit versioned translation, never to REJECT. Observation types are CURRENT_DECLARATION, HISTORICAL_DECLARATION, RESOLVED_VERSION, PATH_STATE and COMPATIBILITY_CONTEXT; the latter is not evidence of target-version installation. Historical positions are BEFORE_RELEASE, AFTER_RELEASE and UNRESOLVED; pair status is separate. Source-origin values must include LOCAL_DOWNSTREAM, COPIED_UPSTREAM and UNRESOLVED, with no automatic acceptance for copied text.

JSONB is permitted only for a bounded, schema-versioned, non-key diagnostic payload such as a provider response metadata excerpt or quarantine detail. It must not hold identity, status, source ref, observation semantics, candidate review, denominator, or finding support edge. The raw payload stays in immutable external snapshots. Any JSONB field must have documented producer/version, maximum size and parsing failure behavior before build; no JSONB column is required by the base tables.

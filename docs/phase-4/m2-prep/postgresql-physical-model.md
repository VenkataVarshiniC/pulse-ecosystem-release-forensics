# Proposed PostgreSQL physical model

**Design only; no DDL or database exists.** This refines [ADR-004](../postgresql-architecture.md) and the [Phase 3 logical model](../../phase-3/logical-data-model.md). All surrogate IDs below are UUID unless stated otherwise. Each FK to a case version carries the same version identity. Every case-scoped child also validates repository membership in that version, either through a composite FK or loader validation where a composite FK would add redundant columns. Tables are append-only after publication except explicitly operational run/task state transitions. A changed interpretation creates a new version/snapshot.

| Schema.table | Exact grain; key | Required typed columns beyond key; FKs and integrity |
| --- | --- | --- |
| ingestion.source_registry | One source definition version; source_id PK, unique (provider, source_type, source_version) | provider/source_type/source_version text, base_locator text nullable, access_class text, created_at timestamptz. No is_authoritative assertion absent a reviewed source rule; actual capture method belongs on artifact. |
| ingestion.collection_run | One collector execution; collection_run_id PK | case_version_id FK core.investigation_case, collector_version/source_plan_version text, started_at timestamptz, completed_at nullable, run_status constrained text, resume_of_run_id self FK nullable. Completed >= started. Connector-assisted evidence need not fake a run. |
| ingestion.collection_task | One planned task in one run; collection_task_id PK, unique (collection_run_id, plan_task_key) | run FK, repository_id FK and case membership validation, source_id FK, task_type/request_locator text, required_flag boolean, attempt_count integer >=0, terminal_status constrained text, started_at/completed_at nullable, error_class text nullable. No artifact_id on task: a task can produce zero or multiple artifacts, and optional not_found has none. |
| ingestion.task_attempt | One attempt; (collection_task_id, attempt_number) PK | attempt_number integer >=1, outcome constrained text, attempted_at timestamptz, source_status text nullable, artifact_digest text nullable. Enables MET-018 without inventing retries from a summary count. |
| ingestion.load_audit | One load attempt; load_id PK | idempotency_key text, input_artifact_id nullable FK, input_digest char(64), target_relation text, loader_version text, loaded_count/rejected_count integer >=0, loaded_at timestamptz, result constrained text, quarantine_ref nullable. Successful key unique; failed attempts remain visible. |
| core.dependency_release | One package release identity; release_id PK | package_ecosystem/package_name_normalized/version text, release_time timestamptz nullable, release_source_id FK, release_artifact_id nullable FK; unique (ecosystem, normalized name, version). Release time null carries unresolved reason, never retrieval time. |
| core.repository | One provider-stable repository identity; repository_id PK | provider text, provider_repository_id text nullable, canonical_full_name text, created_at timestamptz; unique (provider, provider_repository_id) when non-null. Name-only provisional identity is marked unresolved and cannot silently merge. |
| core.repository_alias | One observed name interval/ref; alias_id PK | repository_id FK, full_name text, observed_from/observed_until timestamptz nullable, supporting_artifact_id FK nullable; no invented rename history. |
| core.investigation_case | One frozen definition version; case_version_id PK | case_id UUID, case_version integer >=1, name text, target_release_id FK, window_start/window_end timestamptz, source_plan_version/rule_version text, question_set_version text nullable, status constrained text, created_at timestamptz; unique (case_id, case_version), end >= start. A revision inserts a version. |
| core.cohort_membership | One frozen version × repository; (case_version_id, repository_id) PK | both FKs, selection_method/eligibility_status text, selection_rationale text nullable, included_at timestamptz. Excluded candidates belong in a separate selection audit, never counted as members. No deletion from frozen versions. |
| core.evidence_artifact | One immutable captured payload/ref; artifact_id PK, capture_fingerprint unique | source_id FK, repository_id nullable FK, collection_task_id nullable FK, artifact_type/source_locator/raw_snapshot_uri/media_type text, repository_ref text nullable, source_event_time timestamptz nullable, retrieved_at timestamptz, capture_method constrained text, content_sha256 char(64), parser_version nullable. Source locator, exact query/ref, digest, retrieval and method define captured identity; repeated capture may have same bytes but distinct artifact ID. Raw payload remains external and independently hash-verifiable. |
| core.external_evidence_reference | One provider object reference tied to an artifact; external_ref_id PK | artifact_id FK, provider/source_object_type/provider_object_id/object_locator text, repository_ref/environment_ref nullable, observed_at nullable. Unique (artifact_id, provider, source_object_type, provider_object_id). GitHub, CI, SCA and registry are references, never copied platforms. |
| core.dependency_observation | One parsed claim at artifact/ref/path/type; observation_id PK | case_version_id/repository_id/artifact_id FKs, observation_type constrained text, package_name text, declared_constraint nullable text, resolved_version nullable text, repository_ref/path_ref nullable text, observation_time nullable timestamptz, historical_position constrained text nullable, environment_ref nullable, parser_version/quality_status text. Declaration requires constraint and null resolved version; resolution requires resolved version and null constraint plus ref/environment/time qualification; path absence is a separate type, not a null declaration. No runtime installation assertion from lockfile. |
| core.historical_pair | One case/member/package/path/method pairing decision version; historical_pair_id PK | case_version_id/repository_id FKs, before_observation_id/after_observation_id nullable FKs, pair_status constrained text (PAIRED, AFTER_ONLY, UNRESOLVED, CROSS_FILE_AMBIGUITY), pair_version integer >=1, method_version/reason text. PAIRED needs both exact-ref endpoints and verified before<release<=after; AFTER_ONLY needs after, not before. Cross-file ambiguity is explicit. Unique scoped pair version. |
| core.candidate | One rule firing, never one artifact; candidate_id PK, candidate_fingerprint unique | case_version_id/repository_id/artifact_id FKs, candidate_rule_id/version, lifecycle_category, source_origin, candidate_reason/span_ref/payload_ref text, emitted_at nullable timestamptz, candidate_status text. Fingerprint from case version, baseline, rule/version, artifact, span and firing ordinal; two candidates may cite one PR. |
| core.analyst_review | One review event; review_id PK | candidate_id FK, review_cycle integer >=1, review_sequence integer >=1, reviewer_identity/reason_code/note text nullable, decision constrained text, reviewed_at timestamptz; unique (candidate_id, review_cycle, review_sequence). At most one terminal ACCEPT/REJECT per candidate/cycle via partial unique index; a new cycle is explicit. |
| core.sufficiency_assessment | One case/member/category/question/version; assessment_id PK | case_version_id/repository_id FKs, lifecycle_category/question_id text, assessment_version integer, sufficiency_status constrained text, reason_code text, required_source_set_version/rule_version text, assessed_at timestamptz; unique (case_version_id, repository_id, category, question_id, assessment_version). |
| core.assessment_source_reason | One assessment × required source/reason; (assessment_id, source_id, reason_code) PK | FKs and requirement flag. Enables stage-specific MET-013/015; no inference from repository-level missing-source labels. |
| core.lifecycle_finding | One case/member/category/question/finding version; finding_id PK | case_version_id/repository_id FKs, lifecycle_category/question_id text, finding_version integer, finding_status constrained text, sufficiency_assessment_id FK, rule_version/reason_code text, confidence_level nullable constrained text, created_at timestamptz; unique (case_version_id, repository_id, category, question_id, finding_version). No NO_EVENT_OCCURRED value. |
| core.finding_artifact_support / finding_observation_support / finding_review_support | One finding × typed support ID × role; composite PK | Separate typed FKs to finding and artifact/observation/review, support_role text. Cross-case/member lineage verified before publish; accepted review required for candidate-based YES. Avoids nullable polymorphic edge. |
| core.investigation_disposition | **PROVISIONAL / STAKEHOLDER-GATED**; one human action event if ever validated | disposition_id PK, case_version_id/repository_id nullable FKs, actor/time/reason fields only after role and taxonomy validation. No current operational table or status vocabulary is authorized. |
| core.analysis_snapshot | One immutable publication manifest; analysis_snapshot_id PK, manifest_sha256 unique | case_version_id FK, source_plan_version/rule_version/metric_definition_version/model_version/loader_version text, generated_at timestamptz, state constrained text, supersedes_snapshot_id nullable self FK. Only PUBLISHED snapshots enter marts. |
| core.snapshot_run / snapshot_artifact / snapshot_candidate / snapshot_review / snapshot_assessment / snapshot_finding | One snapshot × typed chosen input ID; corresponding composite PK | Each has analysis_snapshot_id FK and a typed FK to its selected core or ingestion row; artifact edge also stores expected SHA-256 and ordered position. Separate bridges preserve FK integrity while recording exact chosen run, artifact, baseline, review, assessment and finding rows. |
| analytics.* | dbt-produced, snapshot-scoped relations | Defined in [dbt model contracts](dbt-model-contracts.md); not independent forensic sources. |

The typed support bridges allow a finding to cite multiple artifacts, parsed observations or review decisions without losing referential integrity. A finding can have no accepted review when it is UNKNOWN or a properly bounded NO. A YES based on a candidate requires accepted review plus artifact chain; any direct-observation YES requires its own qualified method. Lifecycle categories are evidence classes, not a mandatory chronological progression. See [integrity contract](database-integrity-contract.md) for enforceable versus cross-row rules.

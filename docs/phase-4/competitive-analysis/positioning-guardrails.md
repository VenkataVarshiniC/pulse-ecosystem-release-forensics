# Positioning and do-not-claim rules

The only defensible external wording at this stage is **“designed as a bounded, human-reviewed, release-forensics investigation layer over existing dependency, repository and CI evidence; usefulness pending stakeholder validation.”** The research identifies a possible *composite documentation gap*, not market proof.

Do **not** claim PULSE is first-ever, unique, the only multi-repository dependency view, an update bot, a vulnerability scanner, an SCA replacement, an automatic release-impact platform, or superior to GitHub/Renovate/Snyk/Mend/Socket/Sonatype. Cross-repository and review capabilities are already documented in adjacent products [S05,S09,S18,S19].

Do **not** claim ecosystem-wide visibility, prediction of breakage, causal proof, actual adoption from a version constraint or PR merge, recovery from merge, guaranteed recovery detection, elimination of manual review, saved hours or a market/revenue figure. Phase 4 metrics mark target-version, recovery, recall and time-saved questions unavailable or stakeholder-dependent.

Describe competitor absence only as **“not found in the reviewed public documentation as of 2026-09-27”** and specify the exact combined capability. Internal performance comparisons, product trials and primary user evidence are still missing.

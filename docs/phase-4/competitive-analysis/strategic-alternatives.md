# Strategic alternatives — qualitative decision table

As of **2026-09-27**, official documentation shows strong surrounding-tool coverage, while the user problem and product value remain unvalidated. Criteria are user need, evidence availability, analytical integrity, overlap, differentiation, complexity, review burden, integrations, explainability and validation status. No arbitrary weights, feature scores or financial ROI are assigned.

| Alternative | Evidence-based strengths | Gaps, costs and falsification test | Status |
| --- | --- | --- | --- |
| **A — Existing tools / do nothing** | Dependabot/Renovate, GitHub, SCA, CI, dashboards and scripts already support much of the work [S01–S20]. Minimal new integration or review process. | Manual release-case assembly might be repetitive or error-prone, but frequency, cost and consequence are unmeasured. Ask for a recent case solved adequately with current tools. | **Supported as current default/substitute**, not proof the need is absent. |
| **B — Bounded reporting layer** | Uses existing sources, explicit cohort, source links, human sign-off and UNKNOWN; Phase 2 deterministic reports provide a limited proof of method. Lower workflow complexity than an interactive workspace. | Data acquisition/historical pairing weak; report might not change a decision. Compare a real case report with the user's existing notes. | **Provisionally supported as a research/test slice**, not build authorization. |
| **C — Human-review forensic workspace** | Candidate/review separation directly addresses Phase 2 copied-upstream false positives; could connect source, sufficiency, dissent and cohort comparison. | Reviewer role, queue volume, burden, collaboration and decision value unvalidated; integration cost larger. Observe a real investigation and prototype review handoff before choosing. | **Stakeholder-dependent**. |
| **D — Automated release-impact platform** | Could promise broad triage if evidence and labels existed. | PULSE current target-version/recovery/recall denominators unavailable; false candidates and poor history make automated claims unsafe. Strong overlap with existing risk dashboards [S18,S19]. | **Unsupported now**. |

**Provisional path:** keep A as the realistic status quo and test B on a stakeholder-owned case; move toward C only if observed review decisions require an interactive case workflow. D is rejected at this evidence stage. This is an experiment recommendation, **not a final product recommendation**. Primary stakeholder evidence could favor A and end the product thesis.

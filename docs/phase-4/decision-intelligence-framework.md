# Decision intelligence and consulting evidence

This is a **conditional interpretation template**, not a recommendation engine or a claim that a stakeholder values PULSE. All outputs use the same metric contract, raw provenance and uncertainty as the Product Analyst views. A proposed action owner is a role hypothesis pending discovery, never an assigned person.

| Analytical output / consulting lens | Observation to report | Decision question and evidence | Possible interpretation / next investigation | Business/product implication, uncertainty and owner hypothesis |
| --- | --- | --- | --- | --- |
| Current-state diagnostic / KPI tree | Coverage, outcome and UNKNOWN counts for a named case. | Can the method answer declared questions? MET-001/005/006/012 and source links. | Separate acquisition failure from stage insufficiency. | Could guide evidence-method priority; value to user untested. Proposed evidence-method owner. |
| Funnel breakdown | F0–F5 and optional B path at their own grains. | Where does analysis stop? Frozen membership, tasks, assessments, reviews. | Inspect largest **method gap** and its source class, not “user drop-off.” | Potential collector/context experiment; no labor-saving claim. Proposed analyst/evidence owner. |
| Root-cause quantification | UNKNOWN reason and missing-source distribution. | Which observed gap is actionable? MET-013 with multi-label counts and raw examples. | Test an alternative historical anchor or source access method. | Could change product scope if evidence remains unavailable; method effect unproven. Proposed evidence owner. |
| Segment comparison | Case/package/history/source strata with denominators. | Are patterns confined to a case or method? Cohort table and selection frame. | Check alternative explanations such as plan differences and artifact concentration. | Input to conditional roadmap, not ecosystem estimate. Proposed product/analyst owner. |
| Candidate-error mechanism | Accepted/rejected/unresolved by rule and copied-upstream origin. | Is a rule worth further review or method revision? MET-009/010/011, review ledger. | Audit distinct artifact count and independently label non-emissions before recall claim. | Possible detector experiment; burden and missed-event tradeoff unknown. Proposed rule-review owner. |
| Alternative analysis | PostgreSQL vs current file workflow and other stores; source-method choices. | What minimum architecture is warranted? Demonstrated scale and integrity needs. | Defer platform if source/user gates remain blocked. | Roadmap input, not a build authorization. Proposed architecture owner. |
| Executive dashboard | Case-specific answer, gaps, provenance and next evidence question. | What action can be justified now? Versioned metric + drill-through. | Use conditional recommendation only after source and stakeholder evidence. | Dashboard audience/value unvalidated. Proposed decision owner TBD. |

An eventual recommendation should have: observation → exact metric/evidence → uncertainty and alternative → decision option → testable next investigation → actual owner/approval. Do not prewrite recommendations before analyses. The consulting story is a disciplined diagnosis and option set grounded in the same forensic record, never separate “consulting metrics.”

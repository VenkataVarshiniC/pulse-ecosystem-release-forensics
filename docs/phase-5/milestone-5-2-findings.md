# Phase 5 Milestone 5.2 — FastAPI backend and application API

**Classification: PASS for bounded backend readiness.** The requested published-snapshot read APIs and a fail-closed, fixture-tested review-write gate are implemented. M5.3 can consume the typed `/api/v1` contract and [OpenAPI export](../../data/validation/m5-2-openapi.json) without guessing snapshot, error, pagination, provenance or uncertainty behavior. This does **not** validate the working persona or product usefulness: G8 remains `NOT_YET_VALIDATED`. Production human review is disabled until a legitimate new DRAFT workflow and trusted reviewer-identity policy exist.

## Architecture and endpoint behavior

`src/pulse/api` separates FastAPI HTTP routes, Pydantic schemas, application assembly, parameterized psycopg SQL and review safety. Environment/ignored `.env` configuration reuses the project's isolated local PostgreSQL cluster. Reads use short-lived read-only connections; no ORM or schema migration was introduced. FastAPI and Uvicorn are locked dependencies. The versioned routes provide health, published investigation list/detail, declared repository detail, keyset-paged evidence, scoped artifact provenance, finding list/detail, candidate/review list/detail, and a guarded review POST. See [implementation](m5-2/api-implementation.md), [endpoint contract](m5-2/endpoint-contract.md) and [frontend handoff](m5-2/m5-3-frontend-handoff.md).

Normal reads require one of the two exact approved `PUBLISHED_VALIDATION` snapshot IDs, an existing publication record, a matching case version and declared membership. Selected artifact/candidate/review/assessment/finding bridge tables prevent legacy DRAFT or other-snapshot rows from appearing. Cross-snapshot artifact or finding-support mismatches fail closed. The current two published candidates are read-only: both are distinct firings on one copied-upstream artifact with inherited REJECT, original-review linkage and no new human review. No candidate is separate from a bounded negative finding.

The evidence API preserves collector/connector-assisted/fixture capture method, original ref, digest, nullable event time and retrieval time. Artifact detail exposes only safe public HTTPS locators; local paths, credentialed URLs, restricted sources and raw snapshot URIs are omitted. Findings retain literal UNKNOWN, bounded NO or future qualifying status with sufficiency, source reasons and recorded support IDs. No support edge, zero adoption or recovery rate is synthesized. Evidence pages use immutable artifact UUID keyset order, not event chronology.

The review route has a typed decision/reason/expected-review/idempotency contract. Current published IDs return `PUBLISHED_IMMUTABLE` before a write connection opens. Actual writes require `pulse_test`, `PULSE_API_ENV=test`, explicit eligible DRAFT ID and server-trusted fixture reviewer identity. An isolated transactional test proves one valid review, same-key replay, stale and conflicting rejection, provenance and authority guards, and rollback. Default local policy has **no eligible reviewer or DRAFT target**, so production submission is unavailable. No old DRAFT snapshot was repurposed. See [review safety](m5-2/review-write-safety.md) and [error contract](m5-2/error-contract.md).

## Validation and limits

Locked sync and repository-wide Ruff passed; the full suite passed **194 tests** (one upstream TestClient deprecation warning). The focused API suite passed **20 tests**. A loopback Uvicorn smoke check returned health `ok` and two investigations. Read-only governed replay reconciliation passed after implementation. Live API golden reads reconcile to **2 published investigations, 2+6 members, 2 candidates, 2 inherited REJECT reviews, 40 findings (38 UNKNOWN, two bounded NO, zero positive) and 2 SUFFICIENT/38 INSUFFICIENT assessments**. The committed OpenAPI JSON regenerates identically. Existing database tests ran with full pytest; dbt was not rerun because no analytical model or migration changed. Details are in [testing and validation](m5-2/testing-and-validation.md).

No external evidence was collected. No frozen source capture, published snapshot, metric registry, migration, Power BI artifact or Phase 5 frontend was modified. The operational API deliberately omits case creation, recovery certification, risk scoring, generic SQL/search, AI and enterprise authentication. The exact approved snapshot allowlist must be deliberately updated when a separately governed future publication becomes consumable. M5.3 should use the read contract and show current review actions disabled; M5.4 will validate browser-to-API integration. Stakeholder-dependent workflow and reviewer authority remain provisional.

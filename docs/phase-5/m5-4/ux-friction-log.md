# M5.4 developer/product QA friction log

These observations come from a local technical walkthrough of the actual published validation data on 2026-09-30. They are **not** user research or stakeholder feedback. Severity describes the risk to this bounded workflow, not measured user impact.

| Screen | Observed issue | Severity | Evidence | Resolution / reason |
| --- | --- | --- | --- | --- |
| Repository historical context | The heading counted all historical records as “pairs,” including `AFTER_ONLY` and `UNRESOLVED`. | Repository at narrow width | A first headless capture cropped the right side of the page. Diagnostic capture showed Chrome's requested 390px screenshot was actually a crop of a 504px CSS viewport, so that image alone was not evidence of an app defect. Verified at a true 390px viewport. The pre-fix state was not measured at a true 390px viewport, so this is a defensive refinement rather than a confirmed production defect. |

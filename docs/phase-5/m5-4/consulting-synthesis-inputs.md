# Inputs to later consulting synthesis

This is a preparation record, **not the final recommendation**.

## Problem evidence

PULSE investigated how a dependency release's downstream adoption, compatibility work and public friction could be reconstructed from bounded repositories and preserved sources without mistaking collection success, a declaration, a bot PR or a missing record for a real outcome. [Phase 3's as-is analysis](../../phase-3/root-cause-analysis.md) identifies fragmented evidence and weak decision traceability; the [public PR sample](../../phase-3/secondary-research/github-workflow-analysis.md) is a bounded, bot-heavy observation, not representative user research.

## Current capability

The local product reads two governed published validation snapshots through React, FastAPI and PostgreSQL. It keeps release/cohort/snapshot scope, shows all eight declared members and 40 literal findings, distinguishes UNKNOWN from bounded NO, exposes source/ref/method/digest/clocks, and traces two inherited rejected detector firings to one copied-upstream artifact. The read-only workflow and typed errors were exercised end to end in M5.4.

## Major limitations

There is no current positive supported finding, observed adoption/recovery decision, eligible recovery denominator, representative ecosystem sample, validated reviewer authority or broad private-source policy. The current source-unavailable state is not present in the two live cases. Published reviews are immutable; the UI offers no review write. No stakeholder responses exist, so actual workflow utility, priority and value remain open. Power BI M4.2 is deferred.

## Build findings

The integration preserved exact snapshot membership and distinguished API failure from empty evidence. An imprecise “pairs” count was corrected to “context records,” and the 390px layout was constrained after a true viewport check. The candidate route made copied-upstream origin, inherited REJECT and shared artifact legible; the finding route explicitly disclosed missing support links. Current published data can demonstrate provenance and epistemic restraint, but not a positive decision or live source-unavailable example.

## Product Analytics M3 findings

The [M3 decision memo](../../phase-4/m3/product-analytics-decision-memo.md) found 8/8 core collection versus 38/40 UNKNOWN findings, only one paired pre-release history among eight members, and two rejected firings from one artifact. Its separate public PR sample showed limited visible human discussion. These are diagnostics on bounded populations, not incidence, ROI, user value or production scalability estimates.

## Product implications to test

Question-specific evidence prerequisites and better reason codes appear worth testing before broader automation or metrics. Origin-aware grouping and human review protect against treating copied upstream text as downstream friction. A scoped investigative UI may help explain why a conclusion is unavailable; that usefulness must be tested with actual decision makers rather than inferred from technical correctness.

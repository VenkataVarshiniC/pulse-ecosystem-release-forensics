# Future application acceptance checks

These product checks operationalize, rather than replace, the [Phase 3 acceptance criteria](../../phase-3/acceptance-criteria.md). They are **unexecuted**: no API or frontend is built in M5.1, and user/workflow utility is **PROVISIONAL — STAKEHOLDER VALIDATION PENDING**. Use exact selected case version and snapshot for every check.

| Product check | Future observable pass condition | Existing anchor |
|---|---|---|
| P-01 Navigate bounded investigation | User opens a published case from the list, sees release/window, all declared cohort members and publication/version context, then returns via stable breadcrumb without changing snapshot. Current replay yields exactly two or six members as appropriate. | AC-BR-001-01; AC-SR-001-01; AC-FR-001-01 |
| P-02 Inspect repository | Member detail separates declaration, resolved-version observation, historical pairing, task outcome, candidate count and category findings; AFTER_ONLY is not interpreted as pre-release absence. Out-of-cohort ID returns scoped not-found. | AC-FR-004-01; AC-FR-005-01; AC-FR-006-01 |
| P-03 Inspect evidence | Grouped explorer preserves source type, original permitted locator, exact ref/path, capture method, content digest, task outcome, event time and retrieval time; unknown event time is explicit. Connector-assisted and fixture capture are not called unattended collection. | AC-SR-002-01; AC-NFR-004-01 |
| P-04 Inspect provenance | User can follow every **recorded** candidate/finding support link to its artifact and source context, and return to the source entity. If no support link exists, UI says so. A failed digest/identity check is not shown as verified; credentials are not returned. | AC-BR-003-01; AC-NFR-001-01; AC-NFR-005-01 |
| P-05 Inspect bounded finding | Current replay shows 38 UNKNOWN, two bounded NO and zero positive; state, sufficiency, reason, rule/version and prerequisite gaps remain distinct. Future positive findings require actual support. | AC-BR-002-01; AC-FR-009-01; AC-FR-010-01 |
| P-06 Preserve uncertainty and denominator | Required source failure, missing historical anchor, SOURCE_UNAVAILABLE, INSUFFICIENT and CONFLICTING are explicit when recorded. No candidate never becomes NO. A 0/0 denominator renders “unavailable,” never 0%; loading/API failure never renders zero evidence. | AC-SR-004-01; AC-FR-006-01; AC-FR-009-01; AC-NFR-004-01 |
| P-07 Inspect review lineage | The two current published candidates show separate firings against the same copied-upstream artifact, inherited REJECT with original provenance, and no current ACCEPT. A reviewer click is not fabricated. | AC-FR-007-01; AC-FR-008-01; AC-NFR-001-01 |
| P-08 Guard candidate review | On a new eligible DRAFT candidate with verified human authority, an explicit ACCEPT/REJECT/NEEDS_EVIDENCE plus nonempty reason records reviewer, server time, candidate, rule/artifact and version atomically. Stale/duplicate/unauthorized/invalid requests change nothing and display a specific error. Until those prerequisites exist, review remains read-only. | AC-SR-003-01; AC-FR-008-01; AC-NFR-003-01 |
| P-09 Preserve published/frozen evidence | All current PUBLISHED_VALIDATION snapshots and frozen raw captures remain unchanged through every UI action, including attempted review and retry. Any later conclusion uses separately governed reanalysis/versioning. | AC-NFR-002-01; AC-NFR-003-01 |
| P-10 Handle empty and error states | No cases, no observations, no candidate, missing support link, unavailable source, not-found, network failure and backend failure have distinct copy and next actions; retries retain selected scope and never show a fabricated success. | AC-SR-004-01; AC-NFR-004-01 |

Checks P-01–P-10 are implementation acceptance, not completed stakeholder UAT. A future reviewer should also inspect copy, accessibility and whether this workflow solves a real upgrade decision with genuine G8 responses; passing deterministic examples cannot establish that value.

# Product terminology and copy contract

Use these plain-language labels without changing the governed meaning. Wording and comprehension remain **PROVISIONAL — STAKEHOLDER VALIDATION PENDING**; integrity distinctions are not optional.

| Term | User-facing meaning and preferred copy | Avoid |
|---|---|---|
| Investigation | One declared dependency release, observation window and explicit repository cohort. “Release investigation” | Ecosystem monitor or automatically discovered population. |
| Release | Target upstream package/version and its sourced release boundary. “Target release” | Installed version or downstream deployment. |
| Repository / member | A repository deliberately included in this case denominator. “Declared repository” on cohort views | Treating all GitHub repositories as members. |
| Evidence / artifact | Preserved source capture with locator, method, digest and retrieval context. “Source artifact” | Undocumented claim or unlabeled connector-assisted capture. |
| Observation | Parsed statement from an artifact at a specified ref/time, e.g. declaration or resolution. “Observed declaration” | Adoption, installation or compatibility from declaration alone. |
| Historical pairing | Before/after exact-ref context for one path/method; AFTER_ONLY is unresolved pre-release context. “Paired history” / “After-only history” | Calling after-only a pair or proof of historical absence. |
| Candidate | Tentative rule emission requiring qualification. “Evidence candidate” | Confirmed incident/finding. |
| Review | Human ACCEPT/REJECT/NEEDS_EVIDENCE decision with reason and provenance; inherited decisions reuse an original review. “Inherited prior review” | A machine decision or a fabricated new reviewer action. |
| Finding | Versioned, bounded answer to one repository/category question. “Finding: Unanswered / No qualifying evidence found / Qualifying evidence recorded” | Unscoped release impact or guaranteed chronology. |
| Sufficiency | Whether declared evidence prerequisites for this question are met. “Evidence sufficient/incomplete/source unavailable/conflicting” | Collection success as automatic decision sufficiency. |
| UNKNOWN | No warranted yes or bounded no. “Unanswered — required evidence missing or unresolved” | No issue, zero, blank, or no event. |
| Bounded NO | `NO_QUALIFYING_EVIDENCE_FOUND` only when selected method is sufficient. “No qualifying evidence found under this method” | Universal absence. |
| Unavailable metric / 0/0 | Undefined or ineligible rate with explicit reason. “Unavailable — no eligible observations” | 0%. |
| Source / provenance | Origin, capture method, task/run, event and retrieval clocks, digest and rule lineage. “How this evidence was obtained” | Credentials, sensitive internals, or implied unattended collection. |
| Published validation | Reproducible versioned analytical snapshot for controlled consumption. “Validation snapshot” | Stakeholder-approved product, representativeness, or confirmed adoption/recovery. |

Use “release-associated,” “observed after release,” or “migration-related evidence” when the public record supports temporal association only. Do not write that the release *caused* downstream behavior without separate causal evidence. Lifecycle categories may appear in navigation as topics, not steps in a required order.

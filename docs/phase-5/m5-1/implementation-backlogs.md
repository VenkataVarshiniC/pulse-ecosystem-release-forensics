# Sequenced M5.2 and M5.3 implementation backlogs

These are **plans, not implementation or stakeholder approval**. The application workflow is **PROVISIONAL — STAKEHOLDER VALIDATION PENDING**. Acceptance below is future verification; authoritative Phase 3 requirements and AC remain in [traceability](requirements-to-product-traceability.md). MUST denotes a safe, bounded product contract, not a claim that current published evidence supports every action. Both milestones must preserve exact case/snapshot identity, provenance and UNKNOWN.

## M5.2 — FastAPI/Python backend

| Priority | Capability | Reason | Dependencies | Future acceptance condition |
|---|---|---|---|---|
| MUST | Establish selected-case/snapshot read boundary and response/error envelope | Prevent cross-version joins and false empty/zero | Existing PostgreSQL schema, published snapshot allowlist, [API contract](api-capability-spec.md) | Every read identifies case version, snapshot/state and rule context; missing resource, unavailable source and service failure are distinct; published reads cannot mix DRAFT rows. |
| MUST | List cases and retrieve investigation/cohort | Let a user select a bounded release and see every declared member | Case, release, membership, snapshot | Both published replay cases and all 2/6 members resolve at exact selected snapshots, including zero-candidate members; no impact score. |
| MUST | Retrieve repository investigation and source/historical status | Make evidence limits visible before conclusions | Membership, tasks, observations, historical pairs, assessments | Required failure, AFTER_ONLY, missing anchor and source-unavailable states remain distinct; an out-of-cohort repository returns scoped not-found. |
| MUST | Retrieve grouped evidence and artifact provenance | Support traceable inspection | Core evidence/artifact links, ingestion source/run/task, authorization for locator | Capture method, original allowed locator, ref/path, digest and event/retrieval clocks are accurately typed; credentials/internal storage paths are excluded; pagination is stable and scoped. |
| MUST | Retrieve literal findings, sufficiency and support links | Preserve UNKNOWN/NO distinction | Findings, assessments, reasons, recorded support edges | Current 38 UNKNOWN/two bounded NO/zero positive display literally; no support edge is synthesized and 0/0 remains unavailable. |
| MUST | Retrieve candidates, selected reviews and replay lineage | Show why current firings were rejected | Candidate, review, selected snapshot links, lineage | Two published firings show one shared artifact and inherited REJECT, with original-review provenance; neither appears as an actionable review queue. |
| MUST | Enforce review-write safety gate before exposing submission | A published validation snapshot is immutable | DRAFT candidate eligibility, V005 guards, trusted human reviewer policy, review-cycle semantics | Published/unauthorized/stale/duplicate/invalid submissions fail atomically with no row changes; only an eligible new DRAFT candidate can receive a reasoned human decision. A fixture may verify this contract; current published cases remain read-only. |
| SHOULD | Submit reasoned candidate review when gate is satisfied | Complete UC-03's human qualification path | Previous item plus real eligible DRAFT workflow and identity policy | ACCEPT/REJECT/NEEDS_EVIDENCE records candidate, reviewer, server time, reason, rule/artifact and version once; idempotent retry does not create a second terminal decision; findings change only through separately governed reanalysis. | SHOULD | Thin aggregate summaries from governed marts | Speed overview without recoding metrics | Published mart identity/version checks | Summary reconciles to selected core case/snapshot and preserves denominator/unavailable status; no Power BI-specific API contract. |
| COULD | Optional event-time ordering | Help inspect records with comparable clocks | Verified event timestamps and unknown-time group | Records without comparable event time are grouped as unknown; retrieval time never substitutes for event time. |
| DEFER | Case creation, attention override, closure, recovery write, broad source collection | Owner/criteria and evidence methods remain unvalidated or outside MVP | G8 responses and separate scope decision | No endpoint or schema state is invented in M5.2. |

## M5.3 — React/TypeScript frontend

| Priority | Capability | Reason | Dependencies | Future acceptance condition |
|---|---|---|---|---|
| MUST | Minimal shell, navigation and case/snapshot context | Keep scope obvious across drill-down | M5.2 read envelope, [workflow](product-workflow.md) | Breadcrumbs return to case/member without changing snapshot; no unsupported sidebar or score. |
| MUST | Investigation list and overview | Select bounded case and inspect the whole declared cohort | List/get case and cohort APIs | Every declared member, including no-candidate members, is navigable; release/window/publication state and literal completeness are shown. |
| MUST | Repository investigation | Join source state, historical observation and findings in one operational view | Repository, evidence, findings APIs | Declaration is not shown as installation; AFTER_ONLY and unavailable prerequisites appear next to findings. |
| MUST | Grouped evidence explorer and provenance detail | Show original support and limitations without fabricated chronology | Evidence/artifact APIs | Source, capture method, digest, ref/path and two clocks are distinct; missing event time has an explicit group; public locators are linked only when authorized. |
| MUST | Finding detail with uncertainty rules | Prevent missing data becoming a negative conclusion | Finding/assessment API, [uncertainty contract](uncertainty-ux.md) | UNKNOWN, bounded NO and qualifying are distinct text states; 0/0 is unavailable and empty support links are not invented. |
| MUST | Candidate/review inspection, read-only on published snapshots | Let user understand detector and human decisions | Candidate/review API | Current two inherited REJECTs display as read-only with shared artifact and lineage; no ACCEPT action appears on published snapshots. |
| MUST | Loading, empty, unavailable, network/backend and authorization states | Avoid false zeros and silent failed submissions | Typed API errors, [screen spec](screen-specification.md) | A request failure never renders as no evidence; retry preserves scope; unauthorized/stale/invalid review is actionable and no optimistic decision persists after rejection. |
| SHOULD | Conditional review form when write gate is enabled | Permit a human decision on eligible DRAFT evidence | M5.2 safe submission, reviewer authority, eligible DRAFT target | Requires explicit decision and reason, displays candidate/artifact/rule, handles stale/duplicate rejection, and does not imply instant finding change. Hide/disable when gate is absent. |
| COULD | Optional event-time view | Aid inspection when source clocks support it | Verified M5.2 time ordering | Unknown/incomparable times stay visible, and lifecycle categories are not drawn as a causal sequence. |
| DEFER | Case creation, priority override, closure, dashboards, account administration | No validated product owner or MVP need | G8 and later scope decision | No UI affordance suggests these actions exist. |

M5.2 can start on the read path without waiting for a new review target. M5.3 can start against the typed read contract, with a conditional review form gated until its backend and authority prerequisites exist. M5.4 will verify end-to-end identity, provenance, uncertainty and the safe review path; no such integration has occurred in M5.1.

# Milestone 2 — Historical dependency reconstruction

**Result: PARTIAL.** PULSE automatically discovered path-scoped commits, fetched files at exact SHAs, and reconstructed target-dependency states for `openai/openai-python` and `pandas-dev/pandas`. The release-adjacent target declarations were unchanged in both. `pallets-eco/flask-sqlalchemy` had complementary, incomplete histories across packaging files; no cross-file transition can be established under this bounded strategy. These results do not establish maintainer motivation, installed adoption, runtime compatibility, or lifecycle evidence without review.

## Contract and selection

Run `pulse history cases/<case>.yaml --output-root <new-output-directory>`. The case supplies the target, release timestamp, window, cohort, and configured manifest paths. PULSE checks supported `requirements.txt`, `pyproject.toml`, `setup.py`, and `setup.cfg` paths separately for each declared repository. It calls GitHub's [path-filtered commits endpoint](https://docs.github.com/en/rest/commits/commits) with `path`, `since`, and `until`, consuming all pages through the Milestone 1 client. No user-supplied SHAs or current-path probes select anchors.

For a path, the **before** anchor is its latest commit with committer timestamp at or before the release timestamp; the **after** anchor is its first later commit. Both must fall within `[window-start 00:00 UTC, day-after-window-end 00:00 UTC)`. A commit exactly at release belongs to before. Tied boundary timestamps, malformed commit identities, truncated pagination, and missing sides remain explicit unresolved statuses. The strategy does not substitute the end-of-window repository state for a missing manifest change. A path with no commit in the window has `insufficient_history`, which does not prove that its file was historically absent.

For every available selected ref, PULSE calls GitHub's [contents endpoint](https://docs.github.com/en/rest/repos/contents) with `ref=<exact SHA>`. Each state records the repository, path, SHA, commit and retrieval timestamps, API and blob URLs, `capture_method=collector`, content SHA-256, and its immutable raw snapshot path. The raw commit-list and file-response envelopes use the existing `data/raw/<case>/...` store; typed run results go to `data/interim/<case>/historical/<run-id>/manifest.json`. The live validation files below remain outside Git. A current 404 has no bearing on a file's historical existence; an exact-ref 404 leaves that state unavailable and the transition unknown.

Base64 file content must be inline, valid, UTF-8, and at most 1 MB. Parsing never executes repository code, including `setup.py`. Observations retain the raw declaration, declared and canonical package names, raw and normalized constraints, marker, package extras, direct reference, optional-dependency group, exact SHA, repository timestamp, and source. Dynamic dependency metadata, indirection, unparsed declarations, duplicate target declarations within a group, and missing files block a definitive comparison. Multiple paths remain separate. Opposing introduction/removal across paths is suppressed as possible migration; complementary partial histories receive a migration note but are not combined. Identical declarations in distinct named optional groups may be classified unchanged while retaining every group observation. Only a validated before/after pair can emit a transition. A constraint change does not imply motive or runtime support and cannot bypass the existing candidate/review contract.

`high` means bounded path-changing SHAs and both exact file states parsed without unresolved comparison ambiguity. `medium` denotes selected refs before file validation. Unresolved or unavailable evidence is `low`; confidence does not turn unknown into absence.

`pallets-eco/flask-sqlalchemy` also had only an after-side `setup.cfg` ref, with no target declaration. Other configured paths without in-window commits remained `insufficient_history`. The paired refs were selected because each commit changed the path, not necessarily the target declaration. The selected after ref is the *first later path change*, not the first dependency change. This bounded design can miss a relevant later dependency change and cannot reconstruct a path state whose last modification predates the window. Those are deliberate limits, not negative evidence.

The [Phase 0 SQLAlchemy timeline](../phase-0/forensic-timelines.md) records pandas runtime friction on 2023-01-27, compatibility work merged on 2023-02-09, and pandas 2.0.0 support shipped on 2023-04-03. PULSE's unchanged `>=1.4.16` optional declarations around the release neither contradict nor explain those events: a permissive version declaration is distinct from working runtime compatibility. Phase 0 also records Flask-SQLAlchemy compatibility work and a later release; the incomplete bounded file pairs do not establish that lifecycle sequence from manifests. HTTPX has no Phase 0 cohort comparison; its existing Phase 1 validation is a separate evidence source. No Phase 0 records were changed.

Milestone 2 is **PARTIAL** because automatic exact-ref reconstruction works for two declared repositories, but a common packaging-file migration pattern prevents a complete third pair, and the live release-adjacent pairs show no target-constraint transition. Deterministic tests cover target acceptance/exclusion, introductions/removals, ambiguity, pagination, exact refs, and no code execution; those classifications have not yet been demonstrated as changing target constraints in live cases.

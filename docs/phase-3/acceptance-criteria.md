# Provisional acceptance criteria

Each criterion is a future verification condition linked to exactly one formal requirement in the [specification](requirements-specification.md); none is a UAT result or stakeholder signoff. Inputs described below are test cases to construct later, not claims that new functionality exists. Phase 2 replay artifacts can verify existing portions. A `Then` clause describes the observable outcome and any required negative assertion.

| AC ID / requirement | Given / When / Then |
| --- | --- |
| AC-BR-001-01 / BR-001 | **Given** a release and three explicitly selected repositories, **when** the investigation is recorded, **then** its case boundary and denominator list exactly those three and no unselected repository. |
| AC-BR-002-01 / BR-002 | **Given** one repository with a failed required source and no accepted event, **when** a finding is produced, **then** it is UNKNOWN with the missing source named, not a negative or 0% adoption result. |
| AC-BR-003-01 / BR-003 | **Given** a finding based on an accepted candidate, **when** a reviewer follows its reference, **then** the acceptance decision, original artifact, retrieval context, and case can all be identified. |
| AC-BR-004-01 / BR-004 | **Given** a declared cohort with one evidence gap and one accepted finding, **when** the proposed comparison is viewed, **then** both cases and their distinct reasons appear without an automated business-risk verdict. |
| AC-SR-001-01 / SR-001 | **Given** a proposed case, **when** the investigator reviews it before analysis, **then** package, target version, full selected cohort, and window are visible for confirmation. |
| AC-SR-002-01 / SR-002 | **Given** a candidate from a retrieved PR, **when** its evidence is inspected, **then** source URL/identity, capture method, collection outcome, and original text or digest-linked snapshot are available. |
| AC-SR-003-01 / SR-003 | **Given** three emitted candidates, **when** the analyst records accept, reject, and needs-more-evidence with reasons, **then** each decision remains distinct and only the accepted candidate can enter accepted evidence. |
| AC-SR-004-01 / SR-004 | **Given** a missing historical anchor and otherwise complete public artifacts, **when** the investigator inspects the release-window result, **then** UNKNOWN and the absent anchor are visible. |
| AC-SR-005-01 / SR-005 | **Given** an evidence-based attention suggestion, **when** the decision-maker inspects and overrides it, **then** the source factors and override remain visible and no organizational risk judgment is asserted. |
| AC-SR-006-01 / SR-006 | **Given** a merged PR without installed-version or production evidence, **when** a case disposition is reviewed, **then** PR merge is shown separately and migration/recovery are not marked complete. |
| AC-FR-001-01 / FR-001 | **Given** an otherwise valid case with an empty cohort or an undeclared repository added at analysis time, **when** analysis starts, **then** it is rejected or blocked with the scope error; a valid declared cohort remains unchanged. |
| AC-FR-002-01 / FR-002 | **Given** one verified optional manifest 404 and all required tasks successful, **when** collection finishes, **then** the optional task is not-found and the required set is complete; a failed required task instead remains failed. |
| AC-FR-003-01 / FR-003 | **Given** a snapshot with a mismatched digest or task/run identity, **when** resume or reporting verifies it, **then** reuse is blocked; a matching snapshot retains capture method and original source. |
| AC-FR-004-01 / FR-004 | **Given** a parsed after-release declaration but no paired pre-release anchor, **when** release-window history is assessed, **then** the after-only observation is retained and pre-release declaration remains unresolved. |
| AC-FR-005-01 / FR-005 | **Given** a current permissive declaration and no resolved-version observation, **when** dependency state is reported, **then** current declaration is shown while target-version installation and observed adoption remain unestablished. |
| AC-FR-006-01 / FR-006 | **Given** incomplete required collection or conflicting manifest/lockfile evidence, **when** stage sufficiency is assessed, **then** the matching incomplete/conflicting state and source reasons are emitted and a negative finding is blocked. |
| AC-FR-007-01 / FR-007 | **Given** a Dependabot body whose failure text occurs only in copied upstream notes, **when** candidate generation runs, **then** any emitted candidate identifies that text origin and cannot be accepted automatically as downstream friction. |
| AC-FR-008-01 / FR-008 | **Given** emitted candidates with accept, reject, and needs-more-evidence decisions, **when** findings are derived, **then** only a qualifying accepted candidate enters accepted evidence; each ledger entry retains decision, reason, identity/time where available, and references. |
| AC-FR-009-01 / FR-009 | **Given** zero emitted candidates and incomplete release-boundary context, **when** friction is derived, **then** the result is UNKNOWN rather than NO_QUALIFYING_EVIDENCE_FOUND or NO_EVENT_OCCURRED. |
| AC-FR-010-01 / FR-010 | **Given** identical frozen case, snapshots, rules, and review decisions, **when** reporting is repeated, **then** findings and numerator/denominator meanings match and unavailable adoption/recovery metrics remain explicitly unavailable. |
| AC-FR-011-01 / FR-011 | **Given** a validated triage workflow and a declared cohort containing a repository with a source gap, **when** attention suggestions are shown, **then** the reason is inspectable, an override is recordable, and no automatic risk score is presented as fact. |
| AC-FR-012-01 / FR-012 | **Given** only a merged PR and no defined recovery-eligible set, **when** recovery is requested, **then** the recovery measure is unavailable with denominator/source reasons; no production recovery is inferred. |
| AC-NFR-001-01 / NFR-001 | **Given** a reported accepted finding, **when** an auditor follows its chain, **then** case, task/run, original artifact, candidate, review, and rule identity resolve without an orphan link. |
| AC-NFR-002-01 / NFR-002 | **Given** identical frozen inputs and rule versions, **when** analysis runs twice, **then** normalized findings and defined metrics are analytically equivalent; source retrieval time is not reintroduced as a changed input. |
| AC-NFR-003-01 / NFR-003 | **Given** duplicate terminal reviews or mismatched candidate/artifact identity, **when** a finding is prepared, **then** release is blocked or explicitly unresolved with the inconsistency exposed. |
| AC-NFR-004-01 / NFR-004 | **Given** a case with successful, failed-required, optional-not-found, and not-collected sources, **when** status is reported, **then** all four remain distinct and required-source completion is false. |
| AC-NFR-005-01 / NFR-005 | **Given** a credential-bearing collection configuration, **when** raw evidence and a report are persisted, **then** authentication secrets are absent; a nonpublic source without recorded authorization is not collected. |
| AC-NFR-006-01 / NFR-006 | **Given** a rule-version change, **when** an analyst compares two preserved reports, **then** each report identifies its applicable rule version and the affected findings can be enumerated. |

These criteria are intentionally bounded. They do not assert a latency target, detector precision/recall target, survey result, or completed UAT execution. Stakeholder-dependent criteria may change after Milestone 2A, but integrity-related negative assertions require documented evidence-based review before alteration.

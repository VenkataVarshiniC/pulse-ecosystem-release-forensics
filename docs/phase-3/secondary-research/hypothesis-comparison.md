# Comparison with Milestone 1 hypotheses

This table compares the [Milestone 1 needs and primary-user hypotheses](../stakeholder-needs-hypotheses.md) with the frozen [public PR observations](github-pr-observations.jsonl). `Partially supports` means some observable component appears, not that a stakeholder need was validated. `Not observable from GitHub` means the sampled public PR artifacts cannot answer the question. No H1–H6 hypothesis is promoted to `validated`.

| Hypothesis | Classification | Observed evidence and boundary | Primary-research question |
| --- | --- | --- | --- |
| **H1:** Dependency-upgrade investigation requires evidence from multiple sources. | **Partially supports** | PRs combined dependency diffs, upstream notes, and sometimes review/status comments; [baseplate.py#1054](https://github.com/reddit/baseplate.py/pull/1054) needed a downstream explanation distinct from copied notes. The record does not prove that a user *requires* all sources for their decision. | Which sources did a decision-maker actually inspect, and which changed action? |
| **H2:** Historical/release-time dependency context matters to the decision. | **Partially supports, narrowly** | Old/proposed versions were visible, and [uvicorn#2549](https://github.com/Kludex/uvicorn/pull/2549) retained an older version in the final diff. The study did **not** reconstruct release-time dependency state across repositories or show that stakeholders need it. | At which point in time must dependency state be known? |
| **H3:** Engineers need to prioritize repositories across a portfolio. | **Not observable from GitHub** | Individual PRs expose local repository changes; no sampled artifact establishes portfolio selection or a platform engineer's remit. | Who chooses the repository set and compares priorities across it? |
| **H4:** False-positive or irrelevant signals create review work. | **Not observable from GitHub** | Copied upstream text and bot supersession show potential signal-classification and PR-lifecycle noise. The sample does not document human review effort caused by false PULSE signals; many superseded PRs had no visible human discussion. | What irrelevant signals are actually reviewed, and at what cost? |
| **H5:** Evidence provenance matters to users. | **Not observable from GitHub** | PRs carry source links, but link presence does not establish a user's trust standard or preference. | What source and collection details does the decision-maker require? |
| **H6:** UNKNOWN or insufficient evidence is operationally useful. | **Not observable from GitHub** | The sampled PRs do not show someone using a PULSE-style UNKNOWN result to decide a next action. | What would an inconclusive finding prompt the stakeholder to do? |

**Contradictions:** None of H1–H6 is decisively contradicted by this public sample. The data do challenge any unqualified assumption that every upgrade PR involves substantive human discussion: only **6/20 base PRs** showed visible human interaction, and several of those were approvals rather than reasoning. This does not prove no private investigation occurred.

**Primary-user implication:** The public record supports the existence of local PR reviewers and maintainers in some upgrade decisions, but it does not identify a cross-repository dependency-management engineer or validate that role's needs. The [provisional primary-user hypothesis](../primary-user-hypothesis.md) remains a hypothesis pending genuine Google Form/interview evidence. Do not turn any row above into a formal requirement yet.

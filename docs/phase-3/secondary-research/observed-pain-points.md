# Observable workflow friction and classification hazards

“Friction” here means a visible exception, additional step, or unresolved evidence question in a sampled PR. It is **not** a claim that a contributor felt pain, wasted time, or wanted PULSE. Counts use Sample A (20 base PRs) or Sample B (7 purposive discussion PRs) separately; see [the coded sources](github-pr-observations.jsonl).

| Observable pattern | Direct public evidence | What it does **not** establish |
| --- | --- | --- |
| Test/type-check issue led to an additional code change | In discussion-sample [baseplate.py#1054](https://github.com/reddit/baseplate.py/pull/1054#pullrequestreview-2532549557), review reported test failures; [the inline explanation](https://github.com/reddit/baseplate.py/pull/1054#discussion_r1904554245) described the new mypy typing behavior, and the PR diff changed library code before approval. | No estimate of engineering effort, frequency of such failures, or broader package incompatibility. |
| A grouped proposal was narrowed | In base-sample [uvicorn#2549](https://github.com/Kludex/uvicorn/pull/2549#discussion_r1900374580), a maintainer suggested retaining `websockets==13.1`; the bot proposal body listed 14.1, while the final diff did not upgrade it. | No documented reason beyond the visible suggestion; no proven runtime failure. |
| Bot PR lifecycle churn | **8/20 base** PRs carried an explicit “superseded by” closure comment, such as [baseplate.py#1045](https://github.com/reddit/baseplate.py/pull/1045#issuecomment-2573463429). Three discussion-sample Delphix PRs received human rebase commands followed by Dependabot “already up to date” replies, for example [#598](https://github.com/delphix/virtualization-sdk/pull/598#issuecomment-4136412360). | Supersession is not evidence of failure, wasted review, or a completed rebase. The related PRs were not independent study units. |
| Automation/configuration message | [statys#39](https://github.com/gugarosa/statys/pull/39) received a bot message about a missing `dependencies` label, and later merged. | The message cannot explain the PR's long resolution duration without additional evidence. |
| Upstream text could be misread as downstream evidence | Copied upstream release-note/changelog sections occurred in **13/20 base** and **6/7 discussion** PRs. [baseplate.py#1054](https://github.com/reddit/baseplate.py/pull/1054) demonstrates the distinction between copied upstream notes in the bot body and a separate downstream review statement. | This is a PULSE classification hazard, consistent with Phase 2's false-positive lesson; it is not proof that repository maintainers themselves were confused or burdened. |

No sampled PR provides a basis for claims about frustration, financial cost, hours saved, private investigation, or what users would pay for. The lack of a visible concern in a PR means only that the public record did not show one.

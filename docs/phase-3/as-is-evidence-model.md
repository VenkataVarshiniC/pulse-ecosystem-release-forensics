# As-Is evidence model

This model separates **Phase 2 PULSE system observations** from **Milestone 1A public PR observations** and **Milestone 1 organizational hypotheses**. It is provisional pending genuine Google Form and interview evidence. `Observed` means reproduced within PULSE's frozen Phase 2 cases; `secondary-evidence-supported` means visible in the frozen, bot-initiated GitHub PR sample. Neither status validates a stakeholder workflow. `Not observable` is not evidence that a step does not occur.

| Process element | Evidence source | Evidence status | What is known | What remains unknown |
| --- | --- | --- | --- | --- |
| Upstream release or other update trigger | [Public PR analysis](secondary-research/github-workflow-analysis.md) | `not observable` as a causal trigger | PR bodies often include upstream release context. | Whether a release, schedule, security alert, or another event caused each PR or a broader investigation. |
| Dependency-update PR opened | [27 coded PRs](secondary-research/github-pr-observations.jsonl) | `secondary-evidence-supported` | All 20 base and 7 discussion PRs were Dependabot-initiated in the bounded search frame. | Manual/Renovate paths and unseen organizational intake. |
| Package-file change proposed | [PR codebook/data](secondary-research/github-pr-codebook.md) | `secondary-evidence-supported` | Every selected PR had a Python dependency-file diff; grouped updates occurred. | Whether the proposed version was installed, deployed, or used at runtime. |
| Upstream context attached | [PR analysis](secondary-research/github-workflow-analysis.md) | `secondary-evidence-supported` | Copied release-note/changelog text appeared in 13/20 base and 6/7 purposive discussion PRs. | Whether a reviewer read or needed it; copied text is not downstream failure evidence. |
| Public human review or test discussion | [PR analysis](secondary-research/github-workflow-analysis.md) | `secondary-evidence-supported` | Human interaction was visible in 6/20 base PRs; [one mypy PR](https://github.com/reddit/baseplate.py/pull/1054) documented test failures and a code change. | Full check-run history, private review, time spent, and the decision standard. |
| Local exception handling | [PR observations](secondary-research/github-pr-observations.jsonl) | `secondary-evidence-supported` | Visible cases include retained pin, code change, supersession, rebase command, and up-to-date closure. | Whether these were burdensome or typical outside this bot-centered frame. |
| Local PR disposition | [PR observations](secondary-research/github-pr-observations.jsonl) | `secondary-evidence-supported` | Base: 9 merged, 11 closed; discussion: 4 merged, 3 closed. | Whether merge/closure completed migration or changed production state. |
| Planned public-source collection and reporting | [Phase 2 findings](../phase-2/phase-2-findings.md) | `observed` in PULSE system | Bounded live collection and deterministic reports worked for both frozen cases; core collection was complete for 2/2 and 6/6 repositories. | Whether these sources are sufficient for a stakeholder's actual decision. |
| Release-boundary dependency declaration | [Phase 2 findings](../phase-2/phase-2-findings.md) | `observed` gap in PULSE system | Exact-ref target declarations were observed in 2/8 repositories; only one had a parsed pre-release anchor in a paired path. This is evidence coverage, not adoption. | State for unresolved paths or declarations last changed outside the window. |
| Target-version installation or ordinary runtime/CI resolution | [Phase 2 findings](../phase-2/phase-2-findings.md) | `not observable` with current PULSE inputs | A current/permissive declaration cannot prove target-version use; required inputs were not comprehensively collected. | Which version actually ran and whether it worked. |
| Candidate friction/remediation interpretation | [Phase 2 detector evaluation](../phase-2/detector-evaluation.md) and [PR analysis](secondary-research/github-workflow-analysis.md) | `observed` classifier limit; `secondary-evidence-supported` text provenance | Two Phase 2 rule firings from one bot PR's copied upstream notes were rejected; the public sample also separates copied notes from local statements. | Detector recall and whether false signals create real user review burden. |
| Recovery or organizational completion | [Phase 2 findings](../phase-2/phase-2-findings.md) | `not observable` | Downstream releases were not collected; no recovery-eligible denominator exists. PR merge is only a local disposition. | Stakeholder definition and evidence of migration/production recovery. |
| Selecting a portfolio, assigning priority, escalating work | [Milestone 1 hypotheses](business-problem.md) and [hypothesis comparison](secondary-research/hypothesis-comparison.md) | `hypothesized`; `pending stakeholder validation` | This is a possible decision context for PULSE. | Whether such a cross-repository process exists, who owns it, and what changes decisions. |

The public PR sample is **not** the general dependency-upgrade workflow: it is a first-page, `bump`-title, all-Dependabot frame with 20 base and 7 purposive discussion PRs. Sample B is not pooled with A to estimate prevalence. PULSE's technical findings are not evidence of stakeholder preference or pain. See [the process](as-is-process.md) and [primary-research questions](milestone-2-primary-research-questions.md).

# Logical data dictionary — provisional

Fields are logical business attributes, not physical column/storage types. `Required` means required **when the entity/claim is created**, not that every repository has that observation. `Null` means absent/unrecorded; `UNKNOWN` is a reasoned analytical state on an assessment/finding, never an invented raw value. Sources and allowed values reflect [Phase 2](../phase-2/phase-2-findings.md) where present; proposed values require design validation. [Rules](business-rules.md) control inference.

| Field / entity | Definition; logical type | Source; allowed values | Required; null/UNKNOWN meaning | Rule; quality check; downstream use |
| --- | --- | --- | --- | --- |
| `case_id` / Case | Stable declared investigation identity; identifier | Typed case; unique nonempty ID | Required; null blocks analysis | RULE-011/014; exact case fingerprint match; joins all outputs. |
| `target_package` / Case | Dependency under investigation; package name | Human-declared case; canonical package name | Required; null blocks case | RULE-003; normalized identity; source filtering. |
| `target_version` / Case/Release | Target upstream release version; version label | Human declaration/PyPI; source-preserved value | Required for release case; null blocks analysis | RULE-003; do not equate with installed version; case identity. |
| `release_boundary` / Release | Event time/ref used as release-window boundary; timestamp/ref | PyPI/upstream record; known or unresolved | Required or explicitly unresolved; no fabricated time | RULE-009; timezone/source validity; history pairing. |
| `repository_id` / Repository/Membership | Canonical host/repository identity; identifier | Declared cohort/GitHub metadata | Required for membership; null invalid | RULE-011; unique per case; denominator. |
| `selection_reason` / Membership | Why repository belongs to case; text | Human declaration; recorded rationale | Required in proposed workflow; unvalidated owner | RULE-011; preserve original rationale; cohort audit. |
| `window_start`, `window_end` / Case | Inclusive/exclusive convention to be declared with dates; timestamps | Typed case | Required; null blocks bounded analysis | RULE-011; start before end, explicit timezone; source query bound. |
| `run_id`, `task_id` / Run/Task | Stable execution and planned probe identity; identifiers | Collector journal/task plan | Required if collection attempted | RULE-014; unique and case-linked; replay/provenance. |
| `source_type` / Source/Task | Origin category; enum | Collector plan; e.g. PyPI release, GitHub metadata/issue/PR/commit, manifest/history; future downstream release/CI only if planned | Required for task; null invalid | RULE-010; controlled category and method; sufficiency. |
| `required_flag` / Task | Whether failure blocks required-source completion; Boolean | Frozen task plan | Required; no assumed default | RULE-001; immutable across replay; completeness. |
| `collection_status` / Task | Outcome of planned probe; enum | Run journal; success, optional_not_found, failed, partial, not_collected (source summary), as defined by task type | Required for planned task; null = no trustworthy outcome | RULE-001/010; status consistent with attempts; sufficiency. |
| `source_uri` / Source/Artifact | Original source locator; URI/ref | GitHub/PyPI/raw capture | Required for cited artifact; null prevents accepted citation | RULE-014; link/ref resolves within recorded method; audit. |
| `capture_method` / Artifact | How content was obtained; enum | Snapshot provenance; collector, connector_assisted, fixture | Required; null = provenance incomplete | RULE-014; controlled values; distinguish unattended from validation/fixture. |
| `evidence_sha` / Artifact | Digest or exact Git ref identifying preserved content; digest/ref | Snapshot journal/Git object | Required for immutable collected artifact; null blocks verification | RULE-014; rehash/ref check; replay. |
| `source_event_at`, `captured_at` / Artifact | Event and retrieval times; timestamps | Upstream record/collector | Event time optional if source lacks it; retrieval time required for capture | RULE-008/013; no inferred chronology; timeline/provenance. |
| `ref_sha`, `path`, `declaration_state` / Historical Observation | Exact file state and parsed target-package declaration; ref, path, controlled state | Git exact-ref file/history | Ref/path required if observed; state may be unresolved with reason | RULE-002/003/009; exact ref/path pair; release-boundary assessment. |
| `resolved_version` / Target-Version Observation | Version shown installed/resolved in a named context; version | Future lockfile/runtime/CI evidence; not comprehensively collected in P2 | Optional; null = no version observation, **not zero adoption** | RULE-003; context and artifact required; observed-adoption question. |
| `candidate_id`, `rule_id` / Candidate | Stable emission identity and detector version/rule; identifiers | Frozen candidate baseline | Required for emitted candidate | RULE-004/014; unique, versioned; review linkage. |
| `text_origin` / Candidate | Upstream copied, downstream statement, mixed, or unresolved; enum | PR section/provenance analysis | Required for text candidate in proposed method; unresolved allowed | RULE-007; source-span check; reviewer context. |
| `review_decision` / Review | Analyst disposition; enum | Independent review ledger; accept, reject, needs_more_evidence | Null = unreviewed, never accepted | RULE-004/005; one terminal decision; accepted ledger. |
| `reviewer_id`, `reviewed_at` / Review | Reviewer identity and decision time; identifier/timestamp | Review record | Required where available/authorized; otherwise explicitly absent | RULE-014; no invented person/time; audit. |
| `sufficiency_status` / Assessment | Question-specific source basis; enum | Derived assessment; sufficient, incomplete, unavailable, conflicting | Required for an asserted finding; null blocks release | RULE-009/010; reasons and source set required; finding gate. |
| `finding_status` / Finding | Bounded lifecycle statement; enum | Reviewed ledger + assessment; YES, NO_QUALIFYING_EVIDENCE_FOUND, UNKNOWN | Required when finding issued; null = no finding, not NO | RULE-003–013; stage-valid status; report. |
| `confidence_level` / Finding | Bounded confidence with explicit basis; controlled label and rationale | Analyst/report method; current typed labels where available | Optional until method set; no unsupported numeric score | RULE-014; rationale/links required if shown; communication. |
| `denominator_definition` / Report metric | Which declared subset qualifies for a measure; text/set identity | Case and sufficiency logic | Required for numeric rate; null means metric unavailable | RULE-011/012; no 0% for undefined denominator; report. |
| `disposition` / Human Decision | Human next action or bounded case closure; controlled action plus rationale | Future stakeholder workflow, **not observed** | Optional; null = no recorded decision, not completed | RULE-012; owner/criterion needed; operational handoff. |

`requirement_type` and requirement status belong to the BA specification/RTM, not forensic case data; they are intentionally excluded from this product data model. Value enums are logical contracts for analysis and may need naming refinement during design, but their distinct meanings must remain intact. No retention period or performance SLA is asserted.

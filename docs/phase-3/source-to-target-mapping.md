# Logical source-to-target mapping — provisional

This is a BA interpretation map, **not ETL code or a database schema**. Availability refers to Phase 2 frozen cases, not universal GitHub coverage. Every mapping retains original artifact identity and capture method. The [dictionary](data-dictionary.md) defines logical fields; [rules](business-rules.md) constrain what may be inferred. A source can contain useful context without supporting a lifecycle finding.

| Source | Source field/concept | Target business concept / attribute | Interpretation / transformation | Rule | Quality hazard | Phase 2 availability |
| --- | --- | --- | --- | --- | --- | --- |
| PyPI upstream release metadata | Package, version, release time/source | Dependency Release; Case target/boundary | Preserve published metadata and source; do not infer downstream behavior. | RULE-008/013 | Release timestamp/version identity may differ by source. | Collected for frozen upstream cases. |
| GitHub repository metadata | Owner/name, repository identity | Repository; Cohort Membership reference | Match only repositories already declared in the case; retain aliases/ref. | RULE-011 | Rename or inaccessible repository; no silent cohort drop. | Core metadata complete 2/2 pytest, 6/6 urllib3. |
| Current manifest/requirements | Path and target-package specifier | Evidence Artifact; current declaration observation | Parse package constraint as **current declaration only**; retain path/content digest. | RULE-002/003 | Optional 404, syntax variation, permissive constraint. | Planned optional probes; partial declaration coverage. |
| Lockfile, if accessible | Resolved package version and lock context | Target-Version Observation, when method qualifies | Record resolved version with file ref/time; do not equate lock presence with runtime installation. | RULE-003 | Stale lock, missing environment/platform context. | Not comprehensively used for observed target-version adoption. |
| Historical Git file state | Exact ref SHA, path, content, commit time | Historical Dependency Observation | Parse at exact ref/path and classify pre-/post-release relation; after-only remains insufficient for a release-window negative. | RULE-002/009 | Older unchanged declarations and cross-file moves missed by path-scoped window. | Exact-ref method partial: 2/8 target declarations, one stronger pre-release paired path. |
| GitHub issues | Issue body, timestamps, comments | Evidence Artifact; potential Candidate | Preserve local statements separately from quoted/upstream material; emit tentative candidate only under rule. | RULE-004/007/013 | Search misses version-implicit incidents; body may quote another source. | Planned and collected in frozen cases. |
| GitHub PRs and dependency diff | Body, changed file, status, timestamps | Evidence Artifact; declaration proposal; potential Candidate | PR merge/closure is artifact disposition; proposed version is not installed version. | RULE-003/007/012 | Bot body copied release notes; grouped updates. | PR records collected in P2; dependency-file diffs observed in separate M1A sample, not shown comprehensively acquired by P2. |
| PR comments/reviews | Reviewer statement, decision, timestamp | Evidence Artifact; possible downstream context | Preserve reviewer text and its author/time; source-specific local statement may inform candidate review, not automatic acceptance. | RULE-004/007 | Public comments omit private discussion and systematic CI history. | Not systematically collected/audited in P2; selected connector-assisted M1A comments/reviews were coded. |
| GitHub commits | Commit SHA, message, changed paths | Evidence Artifact; historical anchor/candidate context | Keep exact commit identity; do not treat a matching word in message as accepted remediation. | RULE-004/014 | Commit search/path scope may omit relevant change. | Planned and collected in frozen cases. |
| Downstream releases, if later supported | Version, publication time, notes | Evidence Artifact; possible recovery signal | Only qualify with accepted prior event, defined eligible set/window and reviewed interpretation. | RULE-012/013 | Release does not prove production deployment or universal recovery. | **Not collected** in Phase 2 downstream plans. |
| CI/runtime evidence, if later supported | Check result, environment, resolved version | Target-Version Observation; compatibility context | Tie result to repository/ref/environment; passing check alone is not production recovery. | RULE-003/012 | Incomplete check history and environment mismatch. | Ordinary runtime/CI resolution **not comprehensively collected**. |
| Collector run/task journal | Query, required flag, outcome, attempt, digest | Collection Run/Task; Evidence Source; Sufficiency Assessment | Compare actual task outcomes to declared plan; optional-not-found differs from required failure; source completeness is not analytical sufficiency. | RULE-001/010/014 | Partial pagination, rate-limit, identity mismatch. | Validated in P2 bounded live runs. |
| Frozen candidate baseline and review ledger | Rule, candidate ID, source reference; independent decision | Candidate Signal; Analyst Review; Lifecycle Finding | Keep baseline immutable; only qualifying accepted review enters YES; reject/unresolved stay auditable. | RULE-004/005/006/014 | Copied text, duplicate review, unknown recall. | Existing P2; two firings rejected, zero accepted. |

Logical report fields derive from the declared case, verified task/artifact lineage, historical/target observations where available, review ledger, and question-specific sufficiency. Missing source rows are recorded as availability states rather than fabricated artifacts. A current manifest row cannot fill a historical or installed-version target, and a downstream release row cannot independently establish production recovery.

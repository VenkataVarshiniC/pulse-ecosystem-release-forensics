# Evidence-linked capability prioritization — provisional

These `CAP` IDs are **capability themes, not BR/FR/NFR requirements or acceptance criteria**. MoSCoW is used because stakeholder value, baseline effort, and reach are unknown; RICE scores would be invented. `Must` means essential to a defensible bounded PULSE forensic case *if the product thesis is validated*, not authorization to implement now. Existing architecture can be preserved while its evidence method is improved. Source shorthand: [P2](../phase-2/phase-2-findings.md), [M2 gaps](gap-analysis.md), [M1A PR analysis](secondary-research/github-workflow-analysis.md), [M1 needs hypotheses](stakeholder-needs-hypotheses.md). Every priority remains **provisional pending primary research**; system evidence is not user-demand evidence.

## Architecture retained and evidence method improved

| Retained architecture | Why it still matters | Evidence-method work that remains open |
| --- | --- | --- |
| Typed cases, declared cohorts/windows | Fixes scope and denominator before outcome inspection. | Test a real owned cohort rather than treating research convenience selection as user scope. |
| Authenticated bounded collection, immutable raw evidence, provenance, verified resume | Makes a case reproducible and failure visible. | Add only decision-relevant sources and test access/coverage. |
| Required/optional task semantics | A valid optional 404 differs from a failed required source. | Define new source criticality by question, not globally. |
| Exact-ref historical observations | Avoids substituting current state for past state. | Older anchors and cross-file lineage for release-time context. |
| Separate candidate baseline and independent review | Prevents rule emissions from becoming accepted facts. | Better discovery and upstream/downstream distinction; measure recall and review burden. |
| Stage sufficiency, explicit UNKNOWN, denominator-aware metrics | Prevents false negative/adoption/recovery rates. | Set thresholds for any new installed-version or recovery source. |
| Deterministic report and identity checks | Allows audit and replay. | Test which view and provenance level help real users. |

Portfolio support remains a **Should** hypothesis, not a premise that every repository needs equal analysis. The ability to distinguish routine updates from cases deserving deeper investigation must be tested with actual decision-makers. No ranking algorithm or feature implementation is specified here.

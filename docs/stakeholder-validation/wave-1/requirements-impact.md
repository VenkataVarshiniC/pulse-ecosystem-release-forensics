# Wave 1 requirements impact

Wave 1 does not edit the historical Phase 3 baseline. The table proposes changes for a future governed requirement revision. Wording is condensed from `docs/phase-3/requirements-specification.md`; the source remains authoritative.

Moderate. | Yes: who declares and approves scope. |
| BR-002 | Distinguish supported observations, bounded NO, and unanswered questions. | All encounter insufficient evidence; five prefer explicit uncertainty or UNKNOWN, two confidence scores, and two non-reliance. | `NO_CHANGE`: retain semantics; test presentation separately. | Integrity rule remains aligned. ## New requirement candidate

**W1-NR-01 — workflow integration candidate (`NEW_REQUIREMENT_CANDIDATE`).** The system should fit approved repository, CI, issue, and evidence workflows without requiring duplicate investigation or review. Evidence: integration effort was a barrier for 5/9 and current tools span CI, source hosts, dashboards, scripts, package managers, and update bots. This is a candidate only; it needs workflow observation, integration-boundary definition, security review, and acceptance criteria before entering the baseline.

No existing requirement is weakened or removed by Wave 1. Requirements not listed were not directly addressed and remain unchanged pending future evidence.

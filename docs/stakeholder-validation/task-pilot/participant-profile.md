# Pilot participant profile

## Target

Recruit **1–3 purposively selected participants**. This is bounded task validation, not representative sampling, a usability benchmark, or a statistical experiment.

A preferred participant:

- has personally worked on at least one dependency or package upgrade;
- understands repository, CI, test, issue, pull-request, commit, or runtime evidence;
- can explain an engineering investigation decision and what evidence would change it;
- can use a local read-only web application without sharing private credentials or repository data.

Relevant roles may include Software Engineer, Backend Engineer, Full-Stack Engineer, Technical Lead, repository/service owner, platform/dependency engineer, or security/software-supply-chain engineer. No single title is required.

## Fit screen

Before scheduling, ask only:

1. Have you personally worked on a dependency or package upgrade?
2. Which evidence types did you use to decide what to investigate or whether work was complete?
3. Are you comfortable reasoning through a public, frozen example without entering employer or private-repository information?

Record fit as `ELIGIBLE`, `ELIGIBLE_WITH_LIMITS`, or `NOT_ELIGIBLE`; do not record names, employer, contact details, or the private example itself in the repository.

## Exclusions and limits

Do not recruit solely because someone likes analytics tools. Do not require PULSE familiarity. A participant who helped build the exact interface may complete a dry run but cannot substitute for an independent pilot participant. Prior survey participation may be recorded only as `prior_survey=yes/no/unknown`, without linking a survey respondent ID to a task participant ID.

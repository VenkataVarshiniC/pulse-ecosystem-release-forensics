# Participant task sheet

## Scenario

You are reviewing a frozen public dependency-release investigation in an experimental, read-only PULSE application. Determine what the available information supports and what it does not support. Think aloud as you work.

## Task 1 — Scope comprehension

Open the pytest 8.0.0 investigation. Identify the repositories included in the selected investigation and explain how you know the list is bounded to that selection.

## Task 2 — Finding interpretation

Choose one lifecycle finding. Explain, in your own words, what PULSE is asserting and how confident you would be in that interpretation.

## Task 3 — Uncertainty and bounded conclusions

Locate one finding labeled UNKNOWN and one labeled Bounded NO. Explain what each allows you to conclude and whether you would treat them the same way.

## Task 4 — Evidence trace

Use the application to trace one status or conclusion toward its available evidence or provenance. Describe the chain you can verify and any link or support relationship you cannot verify.

## Task 5 — Candidate and review interpretation

Open the urllib3 2.0.0 investigation and inspect a candidate for `jamesturk/scrapelib`. Explain what the candidate, review, and shared source artifact mean to you. State what, if anything, they prove about migration friction.

## Task 6 — Evidence gap

Identify one conclusion PULSE cannot currently make. Explain which additional evidence or prerequisite you would seek before making a stronger conclusion.

## Task 7 — Next action

If one of these repositories were yours, state what you would investigate or do next, who else might need to decide, and which PULSE information you would use or ignore.

There is no requirement to reach a positive or negative conclusion. If a task cannot be completed from the interface, explain what prevented it.
